A web app that **interviews the user in a chat**, stores the answers in a **validated structured
state**, and generates a draft **Personal Wishes Document**. Built for the Wenup engineering test.

> [!NOTE]
> The document is **fictional and not legal advice**. The app says so in the UI and in the document itself.

## 🚀 Run it

**You need:** Python 3.11+ and an LLM API key (see [🔑 API key](#-api-key) below).

```bash
git clone https://github.com/Madhavi-Gurav/document-intake-assistant.git
cd document-intake-assistant
python start.py
```

> 🪟 On Windows you can just double-click **`start.bat`**. On 🍎 macOS or 🐧 Linux, run `./start.sh`.

**`start.py` does everything:**
1. 📦 Creates a virtual environment and installs the dependencies
2. 🔑 Asks for your API key once, checks it with a real request, and saves it to `.env` (git-ignored)
3. 🌐 Starts the server and opens **http://localhost:8000**

After the first run, `python start.py` starts the app straight away.

## 🔑 API key

The app calls a real LLM through an OpenAI-compatible API. Keys are **never committed**.

| Option | How |
|---|---|
| **Use the key from our email** | Paste it when `start.py` asks for it. |
| **NVIDIA NIM** (default, free) | [build.nvidia.com](https://build.nvidia.com) → sign in → open any model → *Get API Key* (`nvapi-…`) |
| **Google AI Studio** (free) | [aistudio.google.com/apikey](https://aistudio.google.com/apikey). Choose option **2** in `start.py` |

<details>
<summary>⚙️ All settings (<code>.env</code>)</summary>

| Variable | Default | Purpose |
|---|---|---|
| `LLM_PROVIDER` | `nvidia` | `nvidia` or `gemini` |
| `LLM_API_KEY` | — | **Required** |
| `LLM_MODEL` | `nvidia/nemotron-3-super-120b-a12b` | Any chat model the provider serves |
| `LLM_TIMEOUT_SECONDS` | `30` | Per attempt (up to 3 attempts on timeouts, 429s and 5xx) |
| `LLM_EXTRA_BODY` | — | Extra JSON for each request, e.g. `{"chat_template_kwargs": {"enable_thinking": false}}` |
| `LLM_BASE_URL` | preset | Any other OpenAI-compatible endpoint |

</details>

> [!TIP]
> The NIM free tier is sometimes overloaded (`503`). The app retries automatically. If it still
> fails, nothing is saved and the message shows a **Retry** button.

## ✨ What it does

| | Feature |
|---|---|
| 💬 | **Multi-turn interview**: collects name, address, worldwide scope, children, executor, gifts and wishes |
| 🧩 | **Several answers at once**, in any order: "I'm Jane Smith, my brother James is executor, no kids" |
| ✏️ | **Corrections at any time**: "actually make it my friend Sarah", or **Change** in the details panel |
| ❓ | **Follow-up questions** when an answer is partial, vague or contradictory ("no children… my son Tom") |
| 🚫 | **No invented facts**: model output is validated against the user's own words before it's saved |
| 🔁 | **Never re-asks** anything that's already captured; the next question is chosen in code |
| 👀 | **Live preview** of the structured details and the draft document |
| 📥 | **Export** the document: copy, download `.md`, or **Save as PDF** |

## 🧠 How it works

```
 User message
     │
     ▼
 ① LLM extracts proposed updates (JSON) ──► ② parse each field on its own ──► ③ validate
                                                                              │  • evidence quoted from the user
                                                                              │  • names/addresses use only the user's words
                                                                              │  • "none" must actually be said
                                                                              ▼
 ⑥ LLM phrases the reply  ◄── ⑤ code picks the next question ◄── ④ apply + consistency rules
     (template fallback)          (unconfirmed first, then missing)       (corrections, contradictions)
                                                                              │
                                                              document generated by code from
                                                              confirmed values only
```

- **The structured state is the source of truth, not the chat history.** Every field is
  `{value, status, note, evidence}`, where status is `missing`, `unconfirmed` or `confirmed`.
- **Turns are atomic.** If the model fails or returns bad output twice, nothing changes.
- **Separate layers:** UI → API → application logic → LLM client → document generator.

<details>
<summary>📦 Structured state example (confirmed values only)</summary>

```json
{
  "full_name": "Jane Smith",
  "home_address": "12 Oak Lane, Leeds LS1 4AB",
  "covers_worldwide_assets": true,
  "has_children": false,
  "children": [],
  "executor": { "name": "James", "relationship": "brother" },
  "specific_gifts": null,
  "additional_wishes": null
}
```
`null` = not known yet · `[]` = the user confirmed there are none
</details>

## 🔌 REST API

Interactive docs: **http://localhost:8000/docs** (Swagger)

| Method | Endpoint | Returns |
|---|---|---|
| `GET` | `/api/health` | Whether the LLM is configured |
| `POST` | `/api/sessions` | New session with the assistant's greeting |
| `GET` | `/api/sessions/{id}` | Messages, state, progress, document |
| `POST` | `/api/sessions/{id}/messages` | Send `{"message": "..."}` and get the updated session plus what changed |

Errors always look like `{"error": {"code", "message"}}`:
`404 session_not_found` · `422 invalid_request` · `502 llm_unavailable` / `malformed_model_response` · `503 llm_not_configured`

## ⚖️ Key decisions

- **Two LLM calls per turn.** Extraction is validated *before* the reply is written, so the
  assistant never claims to have saved something it rejected.
- **The document is rendered by code, not the LLM.** It can't contain invented clauses and
  always matches the preview.
- **Strict grounding checks.** They sometimes make the assistant re-ask a question, but they
  never store a wrong fact.
- **Tested live on NVIDIA NIM.** `nemotron-3-super-120b` got every extraction right in a
  10-turn test. Other models' results are in [AI_LOG.md](AI_LOG.md).

## 🔭 Production improvements

- 🗄️ Persistent sessions (Postgres/Redis), user accounts, encryption for personal data
- 📊 An evaluation set of scripted conversations run on every prompt or model change
- 🧱 Schema-enforced structured outputs, streaming replies, a circuit breaker for outages
- 🔍 Observability: token and latency metrics, rejected-update rate, logs with personal data redacted
- ✅ A final "review and confirm" step, and a server-side PDF export
- 🔒 Rate limiting, CORS/CSP, secrets from a vault
